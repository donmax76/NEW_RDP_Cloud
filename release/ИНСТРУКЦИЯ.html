Удалённый доступ к Windows через браузер  ·  v1.0.242
Что нового с v1.0.238 → v1.0.242
  • Стрим идёт только по TCP/WSS на порту 443. WebRTC (UDP/STUN/TURN) удалён из браузерного клиента в v1.0.238 — стрим стабильнее, проще проходит корпоративные firewall'ы. На firewall ВПС достаточно открыть только 443/tcp.
  • Качество стрима повышено: H.264 переведён на режим QVBR (Quality-VBR) вместо CBR — чёткий текст и UI на сложных кадрах, экономия трафика на статике. GOP сокращён до 2 секунд — быстрее восстановление после потерь.
  • Новые дефолты: качество 70%, FPS 30, scale 80%, битрейт 8000 kbps (раньше 50/25/60/5000). Подходят для LAN и хорошего интернета. При нестабильной связи браузер пользователя может вручную снизить.
  • Восстановление FPS после перегрузки теперь ведёт обратно к запрошенному клиентом значению (раньше упиралось в 24 FPS).
  • Безопасность ВПС: порт 8080 закрыт, relay слушает только 127.0.0.1 для nginx. Логирование релея понижено до WARNING.
  • Разделы про WebRTC/STUN/TURN ниже сохранены как справка — для будущего восстановления UDP-режима. Сейчас они не используются: пропустите при установке.

🔑 TURN-пароль — синхронизация

В pnpext_config_editor.exe в поле TURN-сервер вы пишете пароль вручную, например: turn:rdp:secret-password@dumanofficial.com:3478.

Этот пароль должен совпадать с тем что прописан в coturn на ВПС2. Если они разные — WebRTC через TURN не заработает.

Проверить пароль coturn на ВПС2

grep "^user=" /etc/turnserver.conf
Выведет, например: user=rdp:secret-password — это и есть текущий пароль.

Если пароли не совпадают

Поменять coturn под ваш собственный пароль (одна команда на ВПС2): 
sed -i 's/^user=rdp:.*/user=rdp:secret-password/' /etc/turnserver.conf
systemctl restart coturn
Замените secret-password на свой пароль из конфига хоста.
⚠ При повторном запуске deploy-vps2.sh или deploy-vps.sh в одиночном режиме — скрипт по умолчанию сгенерирует НОВЫЙ случайный пароль. Чтобы сохранить ваш текущий, передайте его аргументом: 
sudo bash deploy-vps.sh rdp secret-password
sudo bash deploy-vps2.sh rdp secret-password

🔬 Диагностика WebRTC, STUN и TURN

Видеострим работает двумя путями:
  • WebRTC (UDP) — требует открытых портов 3478/udp и 49152-65535/udp на ВПС2. Меньше задержка.
  • WebSocket (TCP/443) — fallback. Работает всегда. Если UDP закрыт — стрим идёт сюда.
Если UDP-порты закрыты — стрим всё равно работает, просто через TCP.

Где смотреть текущий режим

В правом верхнем углу панели во время стрима появляется цветной значок:
🟢 UDP · WebRTC — стрим идёт через WebRTC по UDP. STUN/TURN работают.
🟡 TCP · WebSocket — fallback. WebRTC не подключился, идёт через TCP/443.
Также можно проверить через кнопку 🔍 Check status в Settings → ICE Servers.

Если показывает «STUN/TURN unreachable»

Это значит UDP-порты закрыты или coturn не работает. Диагностика — пошагово:

Шаг 1 — на ВПС2 по SSH

# Работает ли coturn?
systemctl status coturn

# Слушает ли он порт 3478?
ss -tunlp | grep 3478

# Открыты ли порты в firewall?
ufw status numbered

# Резолвится ли домен на этот сервер?
dig dumanofficial.com +short

Шаг 2 — починить если нужно

# Открыть UDP-порты для STUN/TURN
ufw allow 3478/udp
ufw allow 3478/tcp
ufw allow 49152:65535/udp

# Запустить и перезапустить coturn
systemctl enable coturn
systemctl restart coturn

После исправлений

  2. Запустите стрим. Через 5-10 секунд значок в топбаре должен смениться:
    🟡 TCP · WebSocket → 🟢 UDP · WebRTC

Частые причины почему WebRTC не работает

  • UDP-порты закрыты в ufw — самая частая причина. Откройте 3478/udp и 49152-65535/udp.
  • coturn не запущен — systemctl status coturn покажет.
  • Провайдер блокирует UDP — некоторые хостеры режут UDP. Используйте WebSocket fallback (он и так работает).
  • NAT/firewall на стороне браузера — корпоративный firewall может блокировать UDP. Включите Force TURN relay.
  • Пароль TURN не совпадает — см. раздел синхронизации выше.
  • Домен указывает не на ВПС2 — проверьте через dig.

🛡 Защита ВПС от обнаружения и атак

Меры ниже применяются на обоих ВПС (ВПС1 и ВПС2). После их применения атакующий не сможет: найти веб-панель, брутфорсить SSH, сканировать порты, определить версии служб.

1. SSH — сменить порт, отключить вход по паролю

⚠ Перед перезапуском SSH обязательно загрузите SSH-ключ со своего компьютера: 
# На вашей машине:
ssh-keygen                            # если ключа ещё нет
ssh-copy-id -p 22 root@IP_ВПС     # отправить ключ
Иначе после смены SSH-настроек вы потеряете доступ к серверу!
Далее на ВПС: 
# Сменить SSH порт на нестандартный (выберите любой 1024–65535)
sed -i 's/^#\?Port .*/Port 22337/' /etc/ssh/sshd_config

# Запретить вход по паролю — только по ключу
sed -i 's/^#\?PasswordAuthentication .*/PasswordAuthentication no/' /etc/ssh/sshd_config
sed -i 's/^#\?PermitRootLogin .*/PermitRootLogin prohibit-password/' /etc/ssh/sshd_config

systemctl restart ssh

# Открыть новый порт, закрыть старый
ufw allow 22337/tcp
ufw delete allow 22/tcp

2. fail2ban — банит сканеры и брутфорс

apt-get install -y fail2ban

cat > /etc/fail2ban/jail.local << 'EOF'
[DEFAULT]
bantime = 86400
findtime = 600
maxretry = 3

[sshd]
enabled = true
port = 22337
maxretry = 3

[nginx-404-scanner]
enabled = true
filter = nginx-404-scanner
logpath = /var/log/nginx/access.log
maxretry = 8
findtime = 60
bantime = 86400
EOF

cat > /etc/fail2ban/filter.d/nginx-404-scanner.conf << 'EOF'
[Definition]
failregex = ^<HOST> .* "(GET|POST|HEAD) .* HTTP/.*" 404
ignoreregex =
EOF

systemctl enable fail2ban
systemctl restart fail2ban
fail2ban-client status
После этого: 8 обращений к несуществующим страницам за минуту = бан IP на 24 часа.

3. Сменить секретный путь панели

По умолчанию панель открывается по /panel/ — слишком очевидно. Замените на длинный случайный slug: 
# Только на ВПС2
NEW_SLUG="x7k2q9wz4mhn"   # ваш случайный путь, 8–20 символов

sed -i "s|/panel|/${NEW_SLUG}|g" /etc/nginx/sites-available/remote-desktop
nginx -t && systemctl reload nginx
Теперь панель открывается так: https://IP_ВПС2/x7k2q9wz4mhn/
⚠ Запишите slug — без него не зайдёте в панель!

4. Скрыть версию nginx и добавить заголовки безопасности

cat >> /etc/nginx/nginx.conf << 'EOF'

# OPSEC: скрыть версию nginx
server_tokens off;

# Защита от MIME-sniffing и clickjacking
add_header X-Content-Type-Options "nosniff" always;
add_header X-Frame-Options "DENY" always;
add_header Referrer-Policy "no-referrer" always;
EOF

systemctl reload nginx

5. Что должно быть закрыто на firewall

ВПС2 — открыть только:
  • 22337/tcp — SSH (или ваш порт)
  • 443/tcp — HTTPS WebSocket
  • 3478/tcp+udp — STUN/TURN
  • 49152-65535/udp — TURN-медиа

Порт 8080 (Python relay) должен быть закрыт снаружи — relay слушает только 127.0.0.1.

ВПС1 — открыть только:
  • 22337/tcp — SSH
  • 443/tcp — HTTPS WebSocket

Не нужно: 8080, 3478, 49152-65535. coturn и TURN-медиа только на ВПС2.

🔑 TURN password — synchronization

In pnpext_config_editor.exe, the TURN server field uses a password you type manually, e.g. turn:rdp:secret-password@dumanofficial.com:3478.

This password must match the one configured in coturn on VPS2. If they differ — WebRTC via TURN will not work.

Check the coturn password on VPS2

grep "^user=" /etc/turnserver.conf
Outputs something like: user=rdp:secret-password — that's the current password.

If passwords don't match

Update coturn to use your password (one command on VPS2): 
sed -i 's/^user=rdp:.*/user=rdp:secret-password/' /etc/turnserver.conf
systemctl restart coturn
Replace secret-password with the one from your host config.
⚠ When re-running deploy-vps2.sh or deploy-vps.sh in single mode — the script generates a NEW random password by default. To keep your current one, pass it as an argument: 
sudo bash deploy-vps.sh rdp secret-password
sudo bash deploy-vps2.sh rdp secret-password

🔬 WebRTC, STUN and TURN diagnostics

Video stream works two ways:
  • WebRTC (UDP) — requires 3478/udp and 49152-65535/udp open on VPS2. Lower latency.
  • WebSocket (TCP/443) — fallback. Always works. If UDP is closed, stream goes here.
If UDP ports are closed — the stream still works, just over TCP.

In the top-right corner of the panel, during streaming a colored badge appears:

🟡 TCP · WebSocket — fallback. WebRTC didn't connect, going via TCP/443.

dig dumanofficial.com +short

systemctl status coturn

  • UDP ports closed in ufw — most common. Open 3478/udp and 49152-65535/udp.

  • TURN password mismatch — see the synchronization section above.
  • Domain doesn't point to VPS2 — verify with dig.
