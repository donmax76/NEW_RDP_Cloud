PROMETEY — Инструкция по установке

Удалённый доступ к Windows через браузер  ·  v1.0.234

Как это работает

ВАРИАНТ А — Один ВПС ┌─────────────┐ WSS/443 ┌──────────────┐ WSS/443 ┌────────────────┐ │ Хост │────────────▶│ ВПС │◀────────────│ Клиент │ │ (Windows) │ │ (сервер) │ │ (браузер) │ └─────────────┘ └──────────────┘ └────────────────┘ pnpext.sys = IP ВПС relay https://IP_ВПС/panel/ ВАРИАНТ Б — Два ВПС (цепочка) ┌─────────────┐ WSS/443 ┌──────────────┐ WSS/443 ┌──────────────┐ WSS/443 ┌──────────┐ │ Хост │────────────▶│ ВПС1 │────────────▶│ ВПС2 │◀────────────│ Клиент │ │ (Windows) │ │ (цепочка) │ │ (основной) │ │ (браузер)│ └─────────────┘ └──────────────┘ └──────────────┘ └──────────┘ pnpext.sys = IP ВПС1 только relay, relay + веб-панель https://IP_ВПС2 нет веб-панели + stage2 + файлы /panel/
Кратко: Хост подключается к ВПС и ждёт. Клиент открывает браузер → заходит на ВПС → видит экран хоста. ВПС — посредник, ничего не хранит (кроме аудио и скриншотов если включены). При двух ВПС — хост подключается к ВПС1, клиент к ВПС2.
💡 SSL-сертификаты создаются автоматически скриптом прямо на ВПС. Передавать их не нужно.

Что куда копировать — быстрый справочник

🔑 Сначала настройте конфиг: запустите pnpext_config_editor.exe, введите IP ВПС, токен, пароль → «Авто-заполнить STUN/TURN» → «ГЕНЕРИРОВАТЬ pnpext.sys». Только после этого копируйте файлы на хост и запускайте установку.

Структура папки release/

Полное содержимое папки release/:

release/ │ ├── HOST/ ← устанавливается на Windows-компьютер │ ├── install-cmd.bat установка (файлы рядом) │ ├── install-web-cmd.bat установка (файлы скачиваются с ВПС) │ ├── uninstall-cmd.bat полное удаление агента │ ├── pnpext.dll агент удалённого доступа │ ├── pnpext.sys зашифрованный конфиг (генерируется редактором) │ └── pnpext_config_editor.exe GUI-редактор конфига │ └── VPS/ ← загружается на ВПС-сервер(а) ├── deploy-vps.sh установщик (режим [1] одиночный / [2] цепочка ВПС1) ├── deploy-vps2.sh установщик ВПС2 (основной сервер) ├── server.py relay-сервер (Python) ├── index.html веб-панель клиента ├── nginx.conf конфиг nginx (глобальный) ├── nginx-remote-desktop.conf конфиг nginx (сайт) ├── pnpext.dll раздаётся хостам при обновлении ├── pnpext.sys раздаётся хостам при обновлении конфига └── stage2/ модули расширенных функций (только ВПС2/одиночный) ├── filemgr.dll ├── procmgr.dll ├── defender.dll └── sysinfo.dll

Вариант А — Пошаговая установка (один ВПС)

Самый простой случай. Один сервер обслуживает и хост, и клиента.

ВПС Шаг 1 — Загрузить файлы и запустить скрипт

1
Скопируйте release/VPS/ на сервер 
# С вашего компьютера (PowerShell / Terminal):
scp -r release/VPS/* root@IP_ВПС:/root/prometey/
Или через FileZilla / WinSCP — перенесите всё содержимое папки release/VPS/ в /root/prometey/.
2
Подключитесь по SSH и запустите установку 
ssh root@IP_ВПС
cd /root/prometey
chmod +x deploy-vps.sh
sudo bash deploy-vps.sh
3
Выберите режим [1] — Одиночный ВПС Введите 1 и нажмите Enter. Установка займёт 2–4 минуты.
4
Запишите данные из итогового вывода скрипта 
Панель:        https://95.216.10.55/panel/
"server":      "95.216.10.55"
"stun_server": "stun:95.216.10.55:3478"
"turn_server": "turn:rdp:ПАРОЛЬ@95.216.10.55:3478"
Эти данные нужны для настройки хоста.

Скрипт автоматически:

  • Устанавливает nginx, Python 3, coturn
  • Создаёт самоподписанный SSL-сертификат (10 лет)
  • Создаёт рабочие папки: /opt/remotedesk/, audio/, screenshots/, stage2/
  • Копирует server.py, index.html, stage2 DLL, файлы обновлений
  • Настраивает nginx и запускает все службы

ХОСТ Шаг 2 — Настроить конфиг

1
Запустите pnpext_config_editor.exe из папки release/HOST/ Двойной щелчок — окно откроется сразу, Python не нужен.
2
Вкладка «Подключение»:
  • Адрес ВПС — IP вашего ВПС
  • Порт — 443
  • TLS — включено ✓
  • Токен комнаты — любое слово: myroom
  • Пароль — придумайте пароль доступа
3
Нажмите «Авто-заполнить STUN/TURN по адресу ВПС» Программа заполнит вкладку STUN/TURN автоматически.
4
Нажмите «ГЕНЕРИРОВАТЬ pnpext.sys» Файл сохранится рядом в release/HOST/pnpext.sys.

ХОСТ Шаг 3 — Установить агент на Windows

1
Убедитесь что в папке release/HOST/ есть: pnpext.dll, pnpext.sys, install-cmd.bat
2
Правая кнопка мыши на install-cmd.bat → «Запуск от имени администратора» Дождитесь закрытия окна. Служба запустится автоматически.
3
Готово. Агент запущен и автоматически подключится к ВПС.
💡 Если хост и файлы на разных машинах — используйте install-web-cmd.bat. Он скачает pnpext.dll и pnpext.sys с ВПС автоматически.

КЛИЕНТ Шаг 4 — Подключиться

1
Откройте Chrome и перейдите: 
https://IP_ВПС/panel/
2
Предупреждение «Небезопасное соединение» — это нормально.
Нажмите: Дополнительно → Перейти на сайт
3
Введите токен комнаты и пароль (те что задали в конфигураторе) и нажмите Connect.

Вариант Б — Пошаговая установка (два ВПС, цепочка)

Хост → ВПС1 (прозрачный relay) → ВПС2 (основной) ← Клиент.
Для хоста и клиента система выглядит как один сервер.

⚠ Порядок важен: сначала установить ВПС2, потом ВПС1. ВПС1 при настройке должен знать адрес ВПС2.

ВПС2 Шаг 1 — Установить основной сервер

1
Скопировать всё из release/VPS/ на ВПС2 
scp -r release/VPS/* root@IP_ВПС2:/root/prometey/
2
Запустить установщик ВПС2 
ssh root@IP_ВПС2
cd /root/prometey
chmod +x deploy-vps2.sh
sudo bash deploy-vps2.sh
Дождаться окончания. Запомнить IP ВПС2 — он понадобится при настройке ВПС1.
На ВПС2 установится: nginx + веб-панель + server.py + stage2 + coturn.

ВПС1 Шаг 2 — Установить сервер цепочки

1
Скопировать минимальные файлы на ВПС1 
# Минимально необходимое:
scp release/VPS/deploy-vps.sh release/VPS/server.py \
    release/VPS/nginx.conf release/VPS/nginx-remote-desktop.conf \
    root@IP_ВПС1:/root/prometey/

# Или проще — весь пакет (лишнее просто не используется):
scp -r release/VPS/* root@IP_ВПС1:/root/prometey/
2
Запустить установщик, выбрать режим [2] 
ssh root@IP_ВПС1
cd /root/prometey
chmod +x deploy-vps.sh
sudo bash deploy-vps.sh
Выбрать [2] — ВПС1 цепочки.
Ввести адрес ВПС2: wss://IP_ВПС2:443
ВПС1 устанавливает только relay (server.py в режиме цепочки) + nginx + coturn. Веб-панели на ВПС1 нет — это правильно. Прямой запрос через браузер на ВПС1 вернёт 404.

ХОСТ Шаг 3 — Настроить конфиг и установить агент

Запустите pnpext_config_editor.exe, в поле «Адрес ВПС» введите IP ВПС1 (не ВПС2!). Нажмите «Авто-заполнить STUN/TURN» → «ГЕНЕРИРОВАТЬ pnpext.sys».

Запустите install-cmd.bat от имени Администратора.
⚠ IP в конфиге = IP ВПС1. Хост подключается к ВПС1, а не к ВПС2. Клиент подключается к ВПС2. Это нормально — цепочка прозрачна.

КЛИЕНТ Шаг 4 — Подключиться

Клиент открывает браузер и подключается к ВПС2: 
https://IP_ВПС2/panel/
На ВПС1 панели нет. Подключение через ВПС2 — единственный правильный вариант для клиента.

Редактор конфига — pnpext_config_editor.exe

Программа создаёт файл pnpext.sys — зашифрованный конфиг агента. Без этого файла служба не запустится.


Вкладка «Подключение»

  • Адрес ВПС — IP вашего сервера
  • Порт — 443
  • TLS — включено
  • Токен — придумайте: myroom
  • Пароль — пароль доступа

Кнопки

  • Авто-заполнить STUN/TURN — по IP ВПС
  • Генерировать pnpext.sys — сохранить конфиг
  • Открыть pnpext.sys — загрузить существующий
⚠ После изменения IP — обязательно нажать Генерировать pnpext.sys заново и заменить файл на хосте (C:\Windows\System32\drivers\pnpext.sys), затем перезапустить службу.

Обновление

Обновление агента на хосте (через веб-панель)

В браузере откройте вкладку Settings → Host Update:
  1. Нажмите Upload DLL to VPS → выберите новый pnpext.dll
  2. Файл загрузится на ВПС в /var/www/remote-desktop/files/
  3. Нажмите Update Host — хост скачает и заменит DLL автоматически
  4. Служба перезапустится, хост переподключится через ~10 секунд

Обновление сервера на ВПС (через веб-панель)

В браузере откройте вкладку Settings → VPS Deploy:
  • Загрузить server.py → target: relay
  • Загрузить index.html → target: web
  • Загрузить pnpext.dll → target: files
  • После загрузки нажать Restart Relay

Обновление без панели (SSH)

# Скопировать новый server.py на ВПС:
scp release/VPS/server.py root@IP_ВПС:/opt/remotedesk/
scp release/VPS/index.html root@IP_ВПС:/var/www/remote-desktop/

# Перезапустить relay:
systemctl restart rdp-relay
При обновлении сервера файлы нужно копировать в оба места: /opt/remotedesk/ (служба) и /var/www/remote-desktop/ (nginx).

Удаление агента с хоста

Запустите uninstall-cmd.bat от имени Администратора в папке release/HOST/.
Удалится: служба, pnpext.dll, pnpext.sys и все записи в реестре.

Полезные команды на ВПС

# Статус всех сервисов
systemctl status rdp-relay nginx coturn

# Логи в реальном времени
journalctl -u rdp-relay -f

# Перезапустить relay
systemctl restart rdp-relay

# Перезагрузить nginx
nginx -t && systemctl reload nginx

# Проверить занятые порты
ss -tlnp | grep -E "443|8080|3478"

# Проверить куда скопированы файлы
ls -lh /opt/remotedesk/
ls -lh /var/www/remote-desktop/
ls -lh /opt/remotedesk/stage2/

# Создать папки вручную (если не создались)
mkdir -p /opt/remotedesk/audio /opt/remotedesk/screenshots /opt/remotedesk/stage2
chmod 755 /opt/remotedesk/audio /opt/remotedesk/screenshots
systemctl restart rdp-relay

Частые проблемы

Служба на хосте не запускается — «Путь не найден»
→ Файл конфига не был скопирован в нужное место.
→ Решение: убедитесь что pnpext.sys находится рядом с install-cmd.bat при установке.
→ Или вручную: copy /y pnpext.sys %SystemRoot%\System32\drivers\pnpext.sys затем sc start MspIscSvc
Браузер: «Сайт недоступен» или ERR_CONNECTION_REFUSED
→ Проверьте статус: systemctl status rdp-relay nginx
→ Если не запущены: systemctl restart rdp-relay nginx
Браузер показывает 404 вместо панели
→ Убедитесь что в адресе есть /panel/:
  ✓ https://IP/panel/
  ✗ https://IP/ — намеренно возвращает 404 (защита от сканеров)
Хост не появляется в панели
→ Проверьте IP в pnpext.sys — пересоздайте через конфигуратор
→ Токен и пароль должны совпадать с теми что вводите в браузере
→ В варианте Б: IP в конфиге = IP ВПС1, браузер открывает ВПС2
→ Логи: journalctl -u rdp-relay -f — ищите строку с IP хоста
Цепочка: хост не виден на ВПС2, хотя служба работает
→ На ВПС1 проверьте переменные окружения службы:
systemctl cat rdp-relay | grep CHAIN
→ Должны быть строки: RDP_CHAIN_UPSTREAM=wss://IP_ВПС2:443 и RDP_CHAIN_SSL_VERIFY=0
→ Если RDP_CHAIN_SSL_VERIFY=0 отсутствует — переустановите ВПС1 скриптом
Расширенные функции не работают (файловый менеджер, менеджер процессов)
→ Проверьте наличие stage2 DLL: ls /opt/remotedesk/stage2/
→ Должны быть: filemgr.dll procmgr.dll defender.dll sysinfo.dll
→ Если нет — скопируйте из release/VPS/stage2/ в /opt/remotedesk/stage2/
Аудио не записывается
→ mkdir -p /opt/remotedesk/audio && systemctl restart rdp-relay
Предупреждение браузера «Небезопасное соединение»
→ Нормально. Нажмите Дополнительно → Перейти на сайт.
Сертификат самоподписанный — данные всё равно шифруются через TLS.
На ВПС1 (цепочка) нет веб-панели
→ Это правильно. ВПС1 — прозрачный посредник без интерфейса.
→ Панель только на ВПС2: https://IP_ВПС2/panel/

PROMETEY — Installation Guide

Remote access to Windows via browser  ·  v1.0.234

How it works

VARIANT A — Single VPS ┌─────────────┐ WSS/443 ┌──────────────┐ WSS/443 ┌────────────────┐ │ Host │────────────▶│ VPS │◀────────────│ Client │ │ (Windows) │ │ (server) │ │ (browser) │ └─────────────┘ └──────────────┘ └────────────────┘ pnpext.sys = VPS IP relay https://VPS_IP/panel/ VARIANT B — Two VPS (chain) ┌─────────────┐ WSS/443 ┌──────────────┐ WSS/443 ┌──────────────┐ WSS/443 ┌──────────┐ │ Host │────────────▶│ VPS1 │────────────▶│ VPS2 │◀────────────│ Client │ │ (Windows) │ │ (chain) │ │ (main) │ │ (browser)│ └─────────────┘ └──────────────┘ └──────────────┘ └──────────┘ pnpext.sys = VPS1 IP relay only, relay + web panel https://VPS2_IP no web panel + stage2 + files /panel/
In brief: Host connects to the VPS and waits. Client opens browser → connects to VPS → sees host screen. The VPS is a relay. With two VPS — host connects to VPS1, client to VPS2.
💡 SSL certificates are created automatically by the script on the VPS itself.

VPS1 Step 2 — Install the chain server

Run install-cmd.bat as administrator.
⚠ Config IP = VPS1. Host connects to VPS1. Client connects to VPS2. The chain is transparent.

CLIENT Step 4 — Connect

https://VPS2_IP/panel/
Connect via VPS2 — not VPS1. VPS1 has no panel.

Config editor — pnpext_config_editor.exe

Creates pnpext.sys — the encrypted agent config. The service will not start without it.

Connection tab

  • VPS address — server IP
  • Port — 443
  • TLS — enabled
  • Token — e.g. myroom
  • Password — access password

Buttons

  • Auto-fill STUN/TURN — from VPS IP
  • Generate pnpext.sys — save config
  • Open pnpext.sys — load existing
⚠ After changing the IP — regenerate pnpext.sys and replace the file on the host (C:\Windows\System32\drivers\pnpext.sys), then restart the service.

Updates

Update agent on host (via panel)

Settings → Host Update:
  1. Click Upload DLL to VPS → select new pnpext.dll
  2. Click Update Host — host downloads and replaces DLL automatically
  3. Service restarts; host reconnects in ~10 seconds

Update without panel (SSH)

scp release/VPS/server.py root@VPS_IP:/opt/remotedesk/
scp release/VPS/index.html root@VPS_IP:/var/www/remote-desktop/
systemctl restart rdp-relay
Copy to both locations: /opt/remotedesk/ (service) and /var/www/remote-desktop/ (nginx).

Removing the agent

Run uninstall-cmd.bat as administrator from release/HOST/.
Removes: service, pnpext.dll, pnpext.sys, all registry entries.

Useful VPS commands

# Service status
systemctl status rdp-relay nginx coturn

# Real-time logs
journalctl -u rdp-relay -f

# Restart relay
systemctl restart rdp-relay

# Check installed files

Troubleshooting

Service on host fails to start — «Path not found»
→ The config file was not copied to the correct location.
→ Fix: copy /y pnpext.sys %SystemRoot%\System32\drivers\pnpext.sys then sc start MspIscSvc
Browser: «Site unreachable» / ERR_CONNECTION_REFUSED
→ systemctl restart rdp-relay nginx
Browser shows 404 instead of panel
→ ✓ https://IP/panel/   ✗ https://IP/ (intentional — blocks scanners)
Host not visible in panel
→ Check IP in pnpext.sys — regenerate via config editor if wrong
→ Token and password must match what you enter in the browser
→ In Variant B: config IP = VPS1, browser opens VPS2
→ Logs: journalctl -u rdp-relay -f
Chain mode: host not visible on VPS2
→ On VPS1 check: systemctl cat rdp-relay | grep CHAIN
→ Must have: RDP_CHAIN_UPSTREAM=wss://VPS2_IP:443 and RDP_CHAIN_SSL_VERIFY=0
→ If RDP_CHAIN_SSL_VERIFY=0 is missing — reinstall VPS1 using the script
Extended features not working (file manager, processes)
→ ls /opt/remotedesk/stage2/ — must contain 4 DLL files
→ If missing: copy from release/VPS/stage2/ to /opt/remotedesk/stage2/
«Insecure connection» browser warning
→ Normal. Click Advanced → Proceed to site.
Certificate is self-signed — data is still encrypted via TLS.
No web panel on VPS1 (chain mode)
→ Correct. VPS1 is a transparent relay with no interface.
→ Panel is only on VPS2: https://VPS2_IP/panel/
