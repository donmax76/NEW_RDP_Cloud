Ключ шифрования
Сервер шифрует все скриншоты и аудиозаписи на диске. Ключ шифрования не хранится в исходном коде — любой, кто получит доступ к репозиторию или к файлу server.py, не сможет расшифровать данные на сервере.
Ключ живёт только в двух местах На VPS — в защищённом файле /etc/rdp-relay/aes.key (доступен только системному пользователю сервиса, права 600).
Локально у тебя — в файле _gen_aes_key.py (добавлен в .gitignore, в репозиторий не попадает никогда).

🚀Первый деплой на новый VPS

1
Скопировать скрипт на сервер
Выполни с локальной машины. Замени root@185.22.33.44 на своего пользователя и IP VPS.
scp _gen_aes_key.py root@185.22.33.44:~/
2
Подключиться к VPS
ssh root@185.22.33.44
3
Создать файл с ключом
Скрипт сам создаст директорию и файл с правильными правами доступа.
sudo python3 _gen_aes_key.py
Ты должен увидеть:
[OK] Key file written: /etc/rdp-relay/aes.key Key : 3a7f2194c5d26b11... IV : 123456789abcdef0... Mode: 0600 (600)
4
Назначить владельца файла
Нужно только если сервис работает не от root, а от отдельного пользователя (например rdp). Если сервис запускается от root — этот шаг пропустить.
sudo chown rdp /etc/rdp-relay/aes.key
5
Запустить или перезапустить сервис
sudo systemctl restart rdp-relay sudo systemctl status rdp-relay
В статусе должно быть active (running). Если failed — смотри раздел «Неполадки» ниже.
6
Удалить скрипт с сервера
После создания файла ключа скрипт на VPS больше не нужен. Локальная копия при этом остаётся — она пригодится при следующем деплое.
rm ~/\_gen_aes_key.py

🔄Смена ключа шифрования

⚠️ Важно перед сменой ключа После смены ключа все старые зашифрованные файлы (скриншоты, аудио) на VPS станут нечитаемыми. Реши заранее: нужно ли сохранить старые данные, или их можно удалить.
Порядок действий строго такой — нарушать нельзя Если поменять ключ на VPS раньше, чем задеплоить новый DLL на хосты, VPS перестанет принимать данные от хостов со старым ключом.
1
Поменять байты ключа в main.cpp
Найди строки ~3515 и отредактируй:
// main.cpp, строки ~3515–3521 static const BYTE g_aes_key[32] = { 0xНОВЫЕ, 0xБАЙТЫ, ... }; static const BYTE g_aes_iv[16] = { 0xНОВЫЕ, 0xБАЙТЫ, ... };
2
Пересобрать pnpext.dll и задеплоить на хосты
Сначала убедись, что все управляемые машины получили новую версию DLL.
3
Обновить _gen_aes_key.py локально
Открой файл и вписать те же новые байты в HOST_AES_KEY и HOST_AES_IV.
4
Обновить ключ на VPS
scp _gen_aes_key.py root@185.22.33.44:~/ ssh root@185.22.33.44 sudo python3 _gen_aes_key.py --overwrite sudo systemctl restart rdp-relay
5
Очистить старые зашифрованные файлы (если нужно)
Старые файлы зашифрованы прежним ключом — они нечитаемы. Если не нужны, удалить:
sudo rm -rf /opt/remotedesk/screenshots/ sudo rm -rf /opt/remotedesk/audio/ sudo systemctl restart rdp-relay

🔍Если потерял _gen_aes_key.py

Байты ключа всегда есть в main.cpp. Найди строки:

static const BYTE g_aes_key[32] = { 0x3A,0x7F,0x21,0x94,0xC5,0xD2,0x6B,0x11,0x8E,0x4C,0xF9,0x53,0x07,0xB8,0xDA,0x62, 0x19,0xAF,0x33,0xE4,0x5D,0x70,0x88,0x9B,0xC1,0x2E,0x47,0x6A,0x8D,0x90,0xAB,0xCD }; static const BYTE g_aes_iv[16] = { 0x12,0x34,0x56,0x78,0x9A,0xBC,0xDE,0xF0,0x0F,0x1E,0x2D,0x3C,0x4B,0x5A,0x69,0x78 };
1
Скопировать шаблон
cp _gen_aes_key.py.example _gen_aes_key.py
2
Открыть файл и найти секцию с ключами
# Найди эти строки в _gen_aes_key.py: HOST_AES_KEY = bytes([ # ← вставить байты из main.cpp g_aes_key ]) HOST_AES_IV = bytes([ # ← вставить байты из main.cpp g_aes_iv ])
3
Вставить байты из main.cpp
Формат такой же — через запятую, с 0x перед каждым.
HOST_AES_KEY = bytes([ 0x3A, 0x7F, 0x21, 0x94, 0xC5, 0xD2, 0x6B, 0x11, 0x8E, 0x4C, 0xF9, 0x53, 0x07, 0xB8, 0xDA, 0x62, 0x19, 0xAF, 0x33, 0xE4, 0x5D, 0x70, 0x88, 0x9B, 0xC1, 0x2E, 0x47, 0x6A, 0x8D, 0x90, 0xAB, 0xCD, ]) HOST_AES_IV = bytes([ 0x12, 0x34, 0x56, 0x78, 0x9A, 0xBC, 0xDE, 0xF0, 0x0F, 0x1E, 0x2D, 0x3C, 0x4B, 0x5A, 0x69, 0x78, ])
4
Сохранить и действовать как при первом деплое
Дальше — шаги 1–6 из раздела «Первый деплой» выше.

✅Проверка — всё ли работает

Статус сервиса

sudo systemctl status rdp-relay

Должно быть active (running). Если failed — смотри раздел «Неполадки».

Журнал запуска

sudo journalctl -u rdp-relay -n 30

Если ключ загружен корректно — строк [FATAL] AES keys not configured не будет.

Проверить сам файл ключа

# Убедиться что файл существует и права правильные sudo ls -la /etc/rdp-relay/aes.key # Ожидаемый вывод: -rw------- 1 root root ... aes.key # Посмотреть содержимое (два hex-ряда) sudo cat /etc/rdp-relay/aes.key

🛠Устранение неполадок

⛔ [FATAL] AES keys not configured

Файл ключа не найден. Выполни шаги 1–5 из раздела «Первый деплой».

⛔ Cannot read key file

Неправильные права доступа. Исправь:

sudo chmod 600 /etc/rdp-relay/aes.key sudo chown root /etc/rdp-relay/aes.key # или имя пользователя сервиса sudo systemctl restart rdp-relay
⛔ Key must be 32 bytes / IV must be 16 bytes

В файл записаны неверные данные — скорее всего ошибка при копировании байтов. Пересоздай файл: запусти _gen_aes_key.py --overwrite заново.

⚠️ Скриншоты / аудио не отображаются после обновления ключа

Старые файлы зашифрованы прежним ключом — они нечитаемы новым. Удали их и перезапусти сервис:

sudo rm -rf /opt/remotedesk/screenshots/ sudo rm -rf /opt/remotedesk/audio/ sudo systemctl restart rdp-relay

⚙️Альтернативный способ — переменные окружения

Если не хочешь использовать файл, можно передать ключ через systemd.

1
Создать файл с переменными
sudo nano /etc/rdp-relay/secrets.env
Вписать:
RDP_AES_KEY=3a7f2194c5d26b118e4cf95307b8da6219af33e45d70889bc12e476a8d90abcd RDP_AES_IV=123456789abcdef00f1e2d3c4b5a6978
2
Ограничить доступ
sudo chmod 600 /etc/rdp-relay/secrets.env
3
Добавить ссылку в systemd unit
Открой /etc/systemd/system/rdp-relay.service и в секцию [Service] добавь строку:
[Service] EnvironmentFile=/etc/rdp-relay/secrets.env ... остальные параметры ...
4
Перезагрузить systemd и запустить сервис
sudo systemctl daemon-reload sudo systemctl restart rdp-relay

🗂Схема хранения — итого

Локальная машина (у тебя) main.cpp ── байты ключа в C++ исходнике хоста _gen_aes_key.py ── в .gitignore, содержит реальный ключ _gen_aes_key.py.example ── в git, шаблон без ключей (безопасен) VPS сервер /etc/rdp-relay/aes.key ── файл с ключом, chmod 600, не в git server.py ── читает ключ из файла при старте Git-репозиторий server.py ── без ключей _gen_aes_key.py.example ── шаблон без ключей _gen_aes_key.py ── ИГНОРИРУЕТСЯ (.gitignore)
Итог: даже если кто-то получит полный доступ к репозиторию — ключа там нет, и расшифровать файлы на VPS без доступа к серверу невозможно.
