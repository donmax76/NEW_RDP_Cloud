Hissə 2

Sistemin İmkanları

Bütün funksiyalar brauzerdə işləyir. Operatorun kompüterinə heç bir proqram quraşdırılmır. Tam Windows nəzarəti — yalnız bir klik məsafəsində.

🖥️
Real vaxt ekran yayımı
Obyektin ekranını birbaşa brauzerdə görürsünüz. H.264 (QVBR rejimi) və JPEG kodlama. FPS, keyfiyyət, miqyas və bitrate tənzimlənir. Axın WSS/TCP 443 portu üzərindən — korporativ firewall-ları rahat keçir.
📁
Fayl meneceri
Bütün qovluqlara giriş — sistem və gizli daxil. Fayllar yüklənmə, endirmə, silmə və adını dəyişmə. Çoxlu fayl paralel yükləmə.
⚙️
Proseslər və servislər
Bütün işləyən proqramlar və Windows servisləri. İstənilən prosesi bitirə, yeni başlada və ya servis növünü dəyişə bilərsiniz.
💻
Terminal (cmd / PowerShell)
SYSTEM hüquqları ilə tam terminal. İstənilən əmri icra edin — nəticə dərhal görünür. PowerShell və cmd dəstəklənir.
📋
Windows Reyestri
Tam reyestr girişi: açar və dəyərlərin yaradılması, redaktəsi, silinməsi. Bütün məlumat növləri dəstəklənir.
📷
Avtomatik skrinşot
Müəyyən aralıqlarda ekran görüntüsü. Yalnız müəyyən proqramlar üçün və ya həmişə. VPS-də saxlama.
🎤️
Audio: yazma və canlı dinləmə
Mikrofon və sistem sesi. WASAPI loopback — mikrofon aktivlik indikatoru görünmür (hətta aktiv yazma zamanı da). Canlı rejimdə brauzerdə dinləyə bilərsiniz. Opus kodlama.
📈
Aktivlik tarixi
Obyektin nə vaxt yandığını, söndüyünü, kilid vurduğunu izləyir. Ümumi işləmə müddəti, sessiya sayı, dövr statistikası.
👤
Operator idarəetməsi
Bir neçə operator fərqli icazələrlə. Kimisi yalnız ekran görür, kimisi tam girişə malikdir. Hər biri öz girişi ilə daxil olur.
🔄
Uzaqdan yeniləmə
Brauzerdən agentin yeni versiyasını yükləyin — obyekt yükləyib köhnəsini əvəz edər. Fiziki giriş lazım deyil.
🛡️
Mühafizə idarəetməsi
Windows Defender idarəsi, sistem jurnallarının təmizlənməsi, aktivlik izlərinin silinməsi.
🔥
Öz-özünü məhvetmə
Bir düyməylə tam silinmə: servis dayandırılır, fayllar silinir, reyestr təmizlənir. Geriyə heç nə qalmır.
⚙️ Sistem Tələbləri:  Obyekt tərəfi: Windows 11 (x64) — Windows 10 dəstəklənmir   Operator tərəfi: İstənilən OS — brauzer kifayətdir
Hissə 3

Şifrələmə və Kanal Mühafizəsi

Sistemin ən güclü tərəfi — çoxlaylıqlı şifrələmə arxitekturası. Hər bir məlumat parçası bir neçə müstəqil mühafizə layı ilə qorunur. Aşağıda hər layın ətraflı təsviri verilmişdir.

🌐 TLS 1.3 — Transport Şifrələnməsi
Obyekt ↔ VPS ↔ Operator arasındakı bütün trafik TLS 1.3 protokolu ilə şifrələnir. Bu, internetdə mövcud olan ən müasir şifrələmə standartıdır.

Necə işləyir: Əlaqə qurulduqda TLS handshake başa çatır — hər iki tərəf müvəqqəti sessiya açarları yaradır (Ephemeral Diffie-Hellman). Bu açarlar heç vaxt şəbəkədə ötmür, yalnız qısa müddətli RAM-da movcuddur. Hətta keçmiş trafikin bütün paketləri yığılsa da, sessiya açarları olmadan onları oxumaq mümkün deyil (Forward Secrecy).

Nəticədə: Sniffer, ISP və ya hakimiyyət orqanları yalnız təsadüfi baytlar görürlər — məlumat məfhumu, əmrin tipi və ya hədəfi müəyyən etmək mümkün deyil.
TLS_AES_256_GCM_SHA384 · X25519 ECDHE · Port 443 · nginx reverse proxy
🔒 WSS — WebSocket Secure
Bütün əmr və məlumat kanalları WSS (WebSocket over HTTPS) protokolundan istifadə edir. Bu, adi HTTPS bağlantısının üstündən daimi ikitərəfli kanal açır.

Niyə WebSocket? Adi HTTP yalnız "sorğu-cavab" formatında işləyir. WebSocket isə server və klient arasında daimi açıq bağlantı saxlayır — bu, real vaxt ekran yayımı, anında əmr icrası və canlı audio üçün vacibdir.

Maskirovka: Kənarından baxanda bu trafik adi HTTPS veb-sayt açmaqdan fərqlənmir. Heç bir DPI (Deep Packet Inspection) sistemi bunun uzaqdan idarəetmə olduğunu müəyyən edə bilməz.
wss://server:443/host · wss://server:443/ws · Upgrade: websocket
🔐 AES-256-GCM — Modul Şifrələnməsi
Stage-2 modulları (fayl meneceri, proses idarəetməsi, mühafizə) VPS-də AES-256-GCM ilə şifrələnmiş formada saxlanılır.

Açar mexanizmi: Hər obyekt (host) üçün unikal per-room key yaradılır. Bu açar yalnız hədəf obyektin yaddaşında movcuddur. Hətta VPS-ə tam giriş əldə edilsə də, modullar şifrəsizləşdirilə bilməz — çünki açar VPS-də saxlanılmır.

GCM rejimi necə qoruyur: AES-GCM yalnız şifrələmə deyil, həm də autentikləşdirilmiş şifrələmə (AEAD) təklif edir. Mesajın bir baytı belə dəyişdirilsə, bütün blok rədd edilir — manipulyasiya mümkün deyil.

256-bit açar gücü: 2256 mümkün kombinasiya — bu, kainatdakı bütün atomlardan çoxdur. Ən güclü superkompüter belə bu açarın tapılmasına milyard illərdən çox vaxt sərf edər.
AES-256-GCM · 96-bit IV · 128-bit auth tag · per-room key derivation
💾 AES-256-CBC — Konfiq Şifrələnməsi
Agentin parametr fayli (pnpext.sys) diskdə şifrələnmiş formada saxlanılır. Server ünvanı, parol, otaq tokeni — heç nə açıq mətnlə yazılmır.

İkiqat mühafizə: Əvvəlcə açar PBKDF2-HMAC-SHA256 metodu ilə paroldan əldə edilir (100,000 iterasiya — qaba gücə davamlı). Sonra məlumatlar AES-256-CBC ilə şifrələnir.

Fiziki giriş ssenarisi: Hətta kimsə sabit diski çıxarıb analiz etsə belə, pnpext.sys faylini oxumaq mümkün deyil — çünki açar yalnız agentin yaddaşındadır və diskdə heç vaxt saxlanılmır.
AES-256-CBC · PBKDF2-HMAC-SHA256 (100K iter) · random salt · random IV

Hissə 3 (davamı)

Şəbəkə Anonimliyi

Operator heç vaxt aşkarlanmır. VPS başqa ölkədə yerləşir və birbaşa əlaqəni kəsər. Araşdıranlar yalnız VPS-ə qoşulan adi HTTPS trafiki görürlər — bunun arxasında nə olduğunu bilmək mümkün deyil.

🔍 Sniffer / Müstəntəq nə görür
❌Obyektin IP-si — yalnız VPS IP ünvanı ilə əlaqə görünür. Digər tərəfdə kimin olduğu məlum deyil.
❌Operatorun IP-si — obyekt operatorun IP-ni bilmir və öyrənə bilmir. O heç vaxt obyektə göndərilmir.
❌Trafik məzmunu — bütün məlumat axini şifrələnmişdir (TLS 1.3). Sniffer təsadüfi baytlar görür.
❌Aktivlik növü — trafik adi HTTPS kimi görünür. Uzaqdan idarəetmə olduğunu müəyyən etmək mümkün deyil.
✅ VPS necə qoruyur
🛡️Birbaşa əlaqənin kəsilməsi — obyekt yalnız VPS IP-sini bilir. Operator yalnız VPS IP-sini bilir. Bir-birinin ünvanını bilmirlər.
🌎Fərqli yurisdiksiya — başqa ölkədə VPS deməkdir ki, yerli hakimiyyət jurnalları tələb edə bilməz. Beynəlxalq sorğu lazımdır.
🔒İstifadəçi məlumatı yoxdur — parollar yalnız şifrələnmiş hash formada saxlanılır (PBKDF2). Server müsadirə edilsə belə parollar açılmır.
🗑️Əməliyyat jurnalı yoxdur — sessiya tokenları yalnız RAM-da. Yenidən başladıldıqda heç bir iz qalmır.
Araşdırmada maksimum öyrənilə biləcəklər: Obyektdə — onun 443 portunda (HTTPS) VPS IP ünvanına müntəzəm əlaqə qurduğu. Bu hər hansı digər veb-sayta qoşulmaqdan fərqlənmir. Aktiv sessiya ilə VPS-ə fiziki giriş olmadan nə məqsədi, nə operatoru, nə məzmunu müəyyən etmək mümkün deyil.
Hissə 4

Mühafizə Layları

Yeddi müstəqil mühafizə layı sistemi hər tərəfdən qoruyur — şəbəkə səviyyəsindən başlamış fiziki disk analizinə qədər.

1
🌐 Şəbəkə şifrələnməsi — TLS 1.3
Bütün trafik ən müasir TLS 1.3 standartı ilə şifrələnir. Port 443 — standart HTTPS portu: firewall-lar bloklamır, DPI sistemləri adi veb trafik kimi götürür. Forward Secrecy — keçmiş sessiyalar heç vaxt açıla bilməz.
WebSocket Secure (WSS) — HTTPS üstündə daimi ikitərəfli kanal. Trafik veb-sayt açmaqdan fərqlənmir.
Cipher suite: TLS_AES_256_GCM_SHA384, X25519 key exchange, ECDSA sertifikat.
2
🔑 Parol mühafizəsi — PBKDF2
Operator parolları açıq mətnlə heç vaxt saxlanılmır. PBKDF2-HMAC-SHA256 (100,000 iterasiya) + per-user salt ilə hash-lənir. Eyni parollar fərqli hash-lar yaradır. Qaba güclə tapmaq illərlə çəkər.
Session token — server RAM-da birdəfəlik token. Yenidən başladıqda itirilir, oğurlanan token köhnəlir.
3
🧩 Diskdə və yaddaşda iz yoxdur
Diskdə yalnız iki fayl: agent (pnpext.dll) və şifrələnmiş konfiq (pnpext.sys). Heç bir log, keş və ya müvəqqəti fayl yaradılmır. Yaddaşda anonim icra olunan bölgələr yoxdur — yaddaş skaneri yalnız normal svchost.exe görür.
Reflective Load — stage-2 modulları VPS-dən şifrəli yüklənir, RAM-da şifrəsizləşdirilir, PE başlıqları silinir. Forensics skaneri iz tapmaz.
4
🛑 Antiviruslara görünməzlik
Agent fayli (pnpext.dll) statik və dinamik analizdə antivirus şübhəsini oyatmamaq üçün xüsusi hazırlanıb. VirusTotal nəticəsi: Elastic, THOR YARA, Windows Defender — heç biri aşkarlaya bilmir.
/DELAYLOAD — 17 sistem kitabxanası import cədvəlindən gizlədilib.
Microsoft metadata — fayl xüsusiyyətlərindən "Microsoft Corporation" görünür.
String obfuscation — şübhəli sətirlər runtime-da fraqmentlərdən yığılır.
5
👻 İstifadəçiyə tam görünməzlik
Kompüter sahibi agentin işləməsinin heç bir əlamətini görmür: ikon, açılan pəncərə, tepsi qeydi, mikrofon ikonu — heç nə. Agent standart Windows sistem komponenti kimi maskalanır.
WASAPI SYSTEM kontekstindən — mikrofon ikonu görünmür (privacy indicator yalnız istifadəçi sessiyalarında işləyir).
DACL + failureflag=1 — admin belə servisi dayandıra bilmir, avtomatik yenidən başlar.
6
💾 Konfiq şifrələnməsi
pnpext.sys fayli AES-256-CBC + PBKDF2 ilə şifrələnir. Server, parol, otaq tokeni — heç nə açıq mətnlə yox. Fiziki disk analizi belə konfiqin içini oxuya bilməz.
7
🧹 Öz-özünü təmizləmə
Servis dayandırıldıqda bütün modullar yaddaşdan boşaldılır, müvəqqəti fayllar silinir, sistem jurnalları agentlə bağlı qeydlərindən avtomatik təmizlənir. Heç bir iz qalmır.

Раздел 3

Шифрование и защита канала

Сильнейшая сторона системы — многоуровневая архитектура шифрования. Каждый фрагмент данных защищён несколькими независимыми уровнями защиты. Ниже приведено подробное описание каждого уровня.

🌐 TLS 1.3 — Транспортное шифрование
Весь трафик между Объектом ↔ VPS ↔ Оператором шифруется по протоколу TLS 1.3. Это самый современный стандарт шифрования, существующий в интернете.

Как это работает: При установке соединения завершается TLS handshake — обе стороны создают временные сессионные ключи (Ephemeral Diffie-Hellman). Эти ключи никогда не передаются по сети, они существуют только в кратковременной RAM. Даже если все пакеты прошлого трафика собраны, без сессионных ключей прочитать их невозможно (Forward Secrecy).

В результате: Снифер, ISP или органы власти видят только случайные байты — невозможно определить содержание данных, тип команды или цель.
TLS_AES_256_GCM_SHA384 · X25519 ECDHE · Port 443 · nginx reverse proxy
🔒 WSS — WebSocket Secure
Все командные и данные каналы используют протокол WSS (WebSocket over HTTPS). Это открывает постоянный двусторонний канал поверх обычного HTTPS-соединения.

Зачем WebSocket? Обычный HTTP работает только в формате "запрос-ответ". WebSocket же поддерживает постоянное открытое соединение между сервером и клиентом — это необходимо для трансляции экрана в реальном времени, мгновенного выполнения команд и живого аудио.

Маскировка: С внешней стороны этот трафик неотличим от открытия обычного HTTPS-сайта. Ни одна система DPI (Deep Packet Inspection) не может определить, что это удалённое управление.
wss://server:443/host · wss://server:443/ws · Upgrade: websocket
🔐 AES-256-GCM — Шифрование модулей
Модули Stage-2 (файловый менеджер, управление процессами, защита) хранятся на VPS в зашифрованном виде с AES-256-GCM.

Механизм ключа: Для каждого объекта (хоста) создаётся уникальный per-room key. Этот ключ существует только в памяти целевого объекта. Даже при полном доступе к VPS модули не могут быть расшифрованы — ключ не хранится на VPS.

Как защищает режим GCM: AES-GCM предлагает не только шифрование, но и аутентифицированное шифрование (AEAD). Если изменён хотя бы один байт сообщения, весь блок отклоняется — манипуляция невозможна.

256-битная мощь ключа: 2256 возможных комбинаций — это больше, чем всех атомов во Вселенной. Даже самый мощный суперкомпьютер потратит на подбор этого ключа больше миллиардов лет.
AES-256-GCM · 96-bit IV · 128-bit auth tag · per-room key derivation
💾 AES-256-CBC — Шифрование конфига
Файл параметров агента (pnpext.sys) хранится на диске в зашифрованном виде. Адрес сервера, пароль, токен комнаты — ничего не записывается в открытом тексте.

Двойная защита: Сначала ключ извлекается из пароля методом PBKDF2-HMAC-SHA256 (100 000 итераций — устойчив к перебору). Затем данные шифруются AES-256-CBC.

Сценарий физического доступа: Даже если кто-то извлечёт жёсткий диск для анализа, прочитать файл pnpext.sys невозможно — ключ находится только в памяти агента и никогда не хранится на диске.
AES-256-CBC · PBKDF2-HMAC-SHA256 (100K iter) · random salt · random IV

Section 3

Encryption & Channel Security

The system's strongest feature — a multi-layered encryption architecture. Every piece of data is protected by several independent protection layers. Detailed description of each layer is provided below.

🌐 TLS 1.3 — Transport Encryption
All traffic between Object ↔ VPS ↔ Operator is encrypted with TLS 1.3 protocol. This is the most modern encryption standard available on the internet.

How it works: When a connection is established, the TLS handshake completes — both parties generate temporary session keys (Ephemeral Diffie-Hellman). These keys are never transmitted over the network, they exist only in short-lived RAM. Even if all past traffic packets are collected, without session keys they cannot be read (Forward Secrecy).

As a result: Sniffer, ISP or law enforcement only see random bytes — it is impossible to determine the content, command type or target.
TLS_AES_256_GCM_SHA384 · X25519 ECDHE · Port 443 · nginx reverse proxy
🔒 WSS — WebSocket Secure
All command and data channels use the WSS (WebSocket over HTTPS) protocol. This opens a persistent bidirectional channel over a regular HTTPS connection.

Why WebSocket? Regular HTTP only works in "request-response" format. WebSocket maintains a persistent open connection between server and client — this is essential for real-time screen streaming, instant command execution and live audio.

Masking: From the outside this traffic is indistinguishable from opening a regular HTTPS website. No DPI (Deep Packet Inspection) system can determine that this is remote control.
wss://server:443/host · wss://server:443/ws · Upgrade: websocket
🔐 AES-256-GCM — Module Encryption
Stage-2 modules (file manager, process management, defense) are stored on VPS in AES-256-GCM encrypted form.

Key mechanism: A unique per-room key is generated for each object (host). This key exists only in the target object's memory. Even with full access to VPS, modules cannot be decrypted — the key is not stored on VPS.

How GCM mode protects: AES-GCM offers not just encryption but also authenticated encryption (AEAD). If even one byte of a message is altered, the entire block is rejected — manipulation is impossible.

256-bit key strength: 2256 possible combinations — more than all atoms in the universe. Even the most powerful supercomputer would spend more than billions of years finding this key.
AES-256-GCM · 96-bit IV · 128-bit auth tag · per-room key derivation
💾 AES-256-CBC — Config Encryption
The agent's parameter file (pnpext.sys) is stored on disk in encrypted form. Server address, password, room token — nothing is written in plain text.

Double protection: First the key is derived from the password using PBKDF2-HMAC-SHA256 (100,000 iterations — resistant to brute-force). Then the data is encrypted with AES-256-CBC.

Physical access scenario: Even if someone removes the hard drive for analysis, reading the pnpext.sys file is impossible — the key exists only in the agent's memory and is never stored on disk.
AES-256-CBC · PBKDF2-HMAC-SHA256 (100K iter) · random salt · random IV

Section 4

Protection Layers

Seven independent protection layers guard the system from every angle — from the network level to physical disk analysis.

1
🌐 Network encryption — TLS 1.3
All traffic is encrypted with the most modern TLS 1.3 standard. Port 443 — standard HTTPS port: firewalls do not block, DPI systems treat it as regular web traffic. Forward Secrecy — past sessions can never be decrypted.
WebSocket Secure (WSS) — persistent bidirectional channel over HTTPS. Traffic is indistinguishable from opening a website.
Cipher suite: TLS_AES_256_GCM_SHA384, X25519 key exchange, ECDSA certificate.
2
🔑 Password protection — PBKDF2
Operator passwords are never stored in plain text. Hashed with PBKDF2-HMAC-SHA256 (100,000 iterations) + per-user salt. Identical passwords produce different hashes. Brute-force discovery takes years.
Session token — one-time token in server RAM. Lost on restart, stolen token becomes stale.
3
🧩 No traces on disk or in memory
Only two files on disk: agent (pnpext.dll) and encrypted config (pnpext.sys). No logs, cache or temporary files are created. No anonymously executed regions in memory — memory scanner only sees normal svchost.exe.
Reflective Load — stage-2 modules are loaded encrypted from VPS, decrypted in RAM, PE headers erased. Forensics scanner finds no traces.
4
🛑 Invisible to antiviruses
The agent file (pnpext.dll) is specially crafted to avoid raising antivirus suspicion in static and dynamic analysis. VirusTotal result: Elastic, THOR YARA, Windows Defender — none can detect it.
/DELAYLOAD — 17 system libraries hidden from import table.
Microsoft metadata — "Microsoft Corporation" visible in file properties.
String obfuscation — suspicious strings assembled from fragments at runtime.
5
👻 Complete user invisibility
The computer owner sees no signs of the agent running: icon, popup window, tray entry, microphone icon — nothing. The agent masquerades as a standard Windows system component.
WASAPI from SYSTEM context — microphone icon not visible (privacy indicator only works in user sessions).
DACL + failureflag=1 — even admin cannot stop the service, it automatically restarts.
6
💾 Config encryption
pnpext.sys file is encrypted with AES-256-CBC + PBKDF2. Server, password, room token — nothing in plain text. Even physical disk analysis cannot read the config contents.
7
🧹 Self-cleanup
When the service is stopped all modules are unloaded from memory, temporary files are deleted, system logs are automatically cleared of agent-related entries. No traces remain.
